# Архитектурные решения

| # | Решение | Почему |
|---|---|---|
| 1 | Expo SDK 58 (React Native 0.88, Hermes, New Architecture) + Expo Router | Сборка APK без ручной правки нативного кода: все изменения Android идут через config-плагины (`app.config.ts`, `plugins/withAndroidRelease.js`), а папка `android/` генерируется заново. |
| 2 | Монорепо pnpm с `node-linker=hoisted` | Metro и автолинковка Gradle надёжно работают с «плоским» `node_modules`. |
| 3 | Общий пакет `@nexus/core` на чистом TypeScript без зависимостей от React Native | Адаптеры провайдеров, MCP-клиент, цены и цикл агента тестируются в Node (Vitest), а Relay переиспользует протокол. |
| 4 | Три адаптера LLM: OpenAI-совместимый, Anthropic и Gemini | Один OpenAI-совместимый адаптер закрывает DeepSeek, OpenAI, OpenRouter, Groq, Mistral, xAI, Qwen, Kimi, Together, Perplexity, Ollama, LM Studio и свои адреса. Anthropic работает через официальный `@anthropic-ai/sdk` (с `fetch` из `expo/fetch` для стриминга). Gemini — через REST `streamGenerateContent?alt=sse`. |
| 5 | Нативное содержимое ассистента (`raw`) сохраняется и отправляется обратно без изменений | Блоки thinking Claude с подписью и `thoughtSignature` Gemini обязательны при повторной отправке в цепочках с инструментами. Для DeepSeek в рамках текущего хода отправляется `reasoning_content` к вызовам инструментов. |
| 6 | Claude: `thinking: {type: "adaptive", display: "summarized"}` для моделей 4.6+, `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`) для Opus 5.5, Opus 5, Sonnet 5.5 и Fable 5.1, `eager_input_streaming` для инструментов | Это рекомендованные параметры текущего API. Отказ модели (`stop_reason: refusal`) показывается пользователю явно. |
| 7 | Стоимость хранится в микродолларах (целое число) | Нет ошибок округления float. Цена в $ за 1M токенов × число токенов = микродоллары. |
| 8 | Цены по приоритету: свои правки → данные провайдера (листинг OpenRouter) → публичный `/api/v1/models` OpenRouter раз в сутки → встроенная таблица | Актуальные цены без ключей и без своего сервера. Встроенная таблица датирована, в UI есть пометка «проверьте». |
| 9 | Токены берутся из `usage` ответа (с учётом кэша DeepSeek, Anthropic, OpenAI и Gemini). Если провайдер не прислал usage — оценка, помеченная «≈» | Честный учёт, без скрытых допущений. |
| 10 | Свой лёгкий MCP-клиент (`packages/core/src/mcp`) вместо `@modelcontextprotocol/sdk` на телефоне | SDK тянет Node-зависимости (`node:child_process`, ajv). Клиенту нужны JSON-RPC, Streamable HTTP (JSON и SSE-ответы, `Mcp-Session-Id`, повторная инициализация после 404), устаревший SSE и OAuth 2.1 + PKCE + Dynamic Client Registration. Всё это покрыто тестами. |
| 11 | На ПК (Relay) используется официальный `@modelcontextprotocol/sdk` | Запуск stdio-серверов и совместимость с конфигурацией Claude Desktop. |
| 12 | Relay отдаёт один MCP-endpoint `/mcp` (Streamable HTTP, JSON-ответы) | Телефон подключается к ПК как к обычному MCP-серверу, отдельный протокол инструментов не нужен. |
| 13 | Связь с Relay по HTTP в локальной сети или в Tailscale, токен устройства 256 бит, на ПК хранится только scrypt-хеш | Самоподписанный TLS в RN-fetch не поддерживает пиннинг без нативного модуля. Tailscale шифрует трафик (WireGuard). В приложении HTTP без шифрования разрешён только для частных адресов, проверка — `checkUrlSecurity`. |
| 14 | mDNS не используется: QR содержит все IPv4-адреса ПК, Tailscale идёт первым | Без лишнего нативного модуля. Если адрес сменился, приложение само перебирает адреса из QR. |
| 15 | Синхронизация чатов по принципу «последняя запись побеждает» (по `updated_at`) с серверными курсорами | Простая и предсказуемая модель для одного пользователя с несколькими устройствами. Ключи API не синхронизируются никогда. |
| 16 | Ветвление: сообщения образуют дерево (`parent_id`), у чата есть `active_leaf_id` | Перегенерация и правка создают соседние ветки без потери истории, как в Claude. |
| 17 | Запись в БД во время генерации идёт строго последовательно | Связи родитель → потомок не ломаются при быстрых событиях стрима. |
| 18 | Markdown — `react-native-markdown-display` со своими правилами для кода, таблиц и картинок | Блоки кода с копированием и превью HTML/SVG. Удалённые картинки не грузятся автоматически (приватность), открываются по нажатию. |
| 19 | Превью HTML — WebView со строгим CSP. Сеть по умолчанию выключена, разрешаются только CDN, включение — кнопкой | Защита от утечек при запуске сгенерированного кода. |
| 20 | Подпись: переменные окружения → иначе общий ключ из репозитория | APK из CI всегда ставится поверх предыдущего. Для своего ключа есть скрипт и секреты CI. |
| 21 | Разбиение APK по ABI (`arm64-v8a`, `armeabi-v7a`, `universal`) | Меньший размер загрузки. Самообновление выбирает APK под процессор устройства и сверяет SHA-256. |
| 22 | Голосовой ввод — `expo-speech-recognition` (системная служба распознавания Google, непрерывная диктовка с промежуточными результатами). Озвучка — `expo-speech` | Без облачных STT/TTS и ключей. |
| 23 | Во время генерации экран не гаснет (`expo-keep-awake`). Если приложение свёрнуто, по готовности приходит уведомление, по нажатию открывается чат | Длинные ответы не обрываются из-за сна экрана. |
| 24 | История автоматически обрезается целыми ходами под контекстное окно модели (90% минус резерв на ответ), с явным предупреждением в чате | Длинные чаты не падают с ошибкой переполнения контекста; пары tool_call/tool_result не разрываются. |
| 25 | Веб-поиск — встроенный инструмент `web_search` (DuckDuckGo HTML, запасной вариант — Lite), без ключей. Безопасные инструменты только для чтения (`web_search`, `web_fetch`, `datetime_now`, `device_info`) разрешены по умолчанию | Ассистент сам ищет актуальную информацию, не дёргая пользователя подтверждениями. |
| 26 | Не реализовано: LaTeX-рендеринг, приём «Поделиться» из других приложений | Требуют дополнительных нативных модулей. |
